# ZERO Security Transparency

## Current security posture

ZERO publishes architecture and security-process information while keeping claims tied to evidence.

### Publicly documented

- E2EE architecture boundaries
- Device identity and trust model
- Message expiration and cryptographic destruction
- File encryption and secure media boundaries
- Privacy analytics limits
- Infrastructure security requirements
- Production hardening gates
- Vulnerability disclosure lifecycle

### Assessment status

The project documentation explicitly distinguishes implemented contracts from independently verified assessments.

At the current project checkpoint:

- independent cryptographic/security audit: **not completed**
- external penetration test: **not completed**
- production cloud/runtime evidence: **not complete**
- browser/device certification: **not complete**

These statuses must remain synchronized with the project evidence store.

## Security advisories

Advisories use stable ZERO identifiers and a tracked remediation/retest lifecycle.

## Privacy boundary

Public transparency material must never disclose user message content, file content, private keys, recovery secrets, or sensitive infrastructure details.
